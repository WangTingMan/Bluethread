# 蓝牙协议栈介绍

## 概述

本项目是一套完全自研、使用标准 C++ 实现的蓝牙协议栈，不绑定任何特定操作系统内核，具备优秀的跨平台可移植性。只要平台拥有兼容标准 C++ 的编译器即可完成移植，当前已支持 Windows、Android、Linux 以及各类 RTOS 实时操作系统。
协议栈采用模块化架构，基于线程池实现任务调度，模块之间解耦清晰，支持功能裁剪、独立单元测试以及增量迭代开发。

## 核心架构

### 1. 跨平台 C++ 抽象适配层

所有协议核心逻辑均基于标准 C++ 编写。线程管理、休眠、内存分配、定时器、HCI IO 等操作系统相关原语，全部封装在独立的平台适配层中。上层协议模块不存在任何和操作系统硬编码绑定的逻辑；向新平台移植时，仅需要实现少量适配接口。
协议栈支持灵活配置：可根据产品需求选择仅 BR/EDR、仅 BLE，或者双模完整部署。

### 2. 模块化设计

协议栈按照蓝牙规范分层拆分为独立模块，包含 HCI、L2CAP、SDP、RFCOMM、HID、A2DP、LE Audio 等。
- 禁止跨模块直接访问内部成员变量；
- 模块之间仅通过任务 / 消息投递完成交互；
- 模块支持串行执行模式：框架保证同一个模块下所有任务不会并发运行。每次任务调度可以由不同工作线程承接，但模块代码不会并行执行，以此减少锁竞争、提升运行性能；
- 全局设备信息（设备名称、控制器参数等）由独立的信息管理模块统一维护，类似受保护的数据库，提供线程安全的查询与修改接口。

### 3. 基于线程池的任务调度器

所有协议事件、HCI 接收报文、状态机跳转都封装为任务，由内置线程池分发调度。
- 各类状态机（ACL 状态机、L2CAP 通道状态机等）全部运行在任务上下文内，避免在中断上下文放置复杂业务逻辑，便于调试与信令流程抓踪；
- 统一任务模型，待清理报文任务、L2CAP 信令解析、ACL 连接管理等操作都复用这套机制。

## 主要特性

- **已完成模块：完整SDP、L2CAP、RFCOMM、SPP的实现；配对处理、设备可发现性配置等基础GAP能力；**
- 支持 BR/EDR 与 BLE 双模蓝牙；
- 完整 L2CAP 信令实现：连接请求、配置协商、QoS、扩展流规格、重传与流控选项解析；
- 健壮的报文解析器：支持畸形报文校验、载荷截断检测，对非法信令做合理拒绝，抵御对端异常报文；
- 细粒度功能裁剪，可在资源受限嵌入式设备上降低内存占用；
- 协议业务逻辑与平台相关代码清晰隔离，降低多产品量产维护成本。
